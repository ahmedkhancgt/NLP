# Chapter 21: Natural Language Processing

## Core Idea
NLP techniques are built up from simple to sophisticated: word clouds (mostly useless, improved by making axes meaningful), n-gram language models (bigram/trigram, learned from a corpus), formal grammars (rule-based generation/parsing), Gibbs sampling (sampling from distributions via conditional probabilities), LDA topic modeling (unsupervised topic discovery via Gibbs sampling), word vectors/embeddings (learned via a skip-gram neural net), and recurrent neural networks (for sequence modeling, demonstrated with a character-level RNN that generates startup names).

## Frameworks Introduced
- **n-gram language models**: precompute `transitions[prev] -> [possible next words]` (bigram) or `trigram_transitions[(prev,current)] -> [next]` from a corpus; generate text by randomly walking these transitions until hitting a period.
  - When to use: quick, from-scratch statistical text generation; trigrams produce more coherent (but more plagiaristic) text than bigrams because fewer choices exist at each step.
- **Formal grammars**: define `Grammar = Dict[str, List[str]]` production rules (nonterminals prefixed `_`), recursively `expand` a start symbol until only terminals remain.
  - When to use: generating structurally-valid sentences (or, run in reverse, parsing sentences into their grammatical structure) with more control than n-grams.
- **Gibbs sampling**: when only conditional distributions (not the joint) are known, alternately resample each variable conditional on the current value of the others; after enough iterations the result approximates a sample from the true joint distribution.
  - When to use: sampling from multidimensional distributions you can't sample directly but can condition on — the technique underlying the chapter's LDA implementation.
- **Latent Dirichlet Allocation (LDA) topic modeling**: assumes K topics, each with a word-distribution, and each document with a topic-mixture; words are generated by (pick topic from document's mixture) then (pick word from topic's distribution). Fit via Gibbs sampling: randomly initialize topic assignments, then repeatedly resample each word's topic based on `p_word_given_topic * p_topic_given_document`.
  - When to use: discovering latent thematic structure across a corpus of documents (e.g., clustering user interests into unnamed topics you then interpret and name yourself).
- **Word vectors / embeddings (skip-gram)**: train a small neural net to predict nearby words from a given word; the trained embedding lookup table's rows become dense word vectors capturing semantic/syntactic similarity, measurable via cosine similarity.
  - When to use: representing words as dense vectors usable in downstream ML models, enabling similarity/analogy reasoning (e.g., king - man + woman ≈ queen).
- **Recurrent Neural Networks (RNN)**: maintain a hidden state across sequential inputs, combining each new input with the current hidden state (`output = dot(w,input) + dot(u,hidden) + b`, then `tanh`) to produce both an output and the next hidden state.
  - When to use: sequence data where order matters ("dog bites man" != "man bites dog") and fixed-size aggregation (sum/average) would lose that information.

## Key Concepts
- **Word cloud (and why to avoid naive ones)**: sizing words by frequency with meaningless 2D placement conveys no real information; better to map word position to meaningful axes (e.g., job-posting frequency vs. résumé frequency).
- **Bigram / trigram**: word (or n-word) sequences used to model local language statistics; trigrams constrain generation more, producing more fluent but more derivative text.
- **Terminal vs. nonterminal (grammar)**: terminals are literal words needing no further expansion; nonterminals (book's convention: leading underscore) expand via a randomly chosen production rule.
- **Cosine similarity**: `dot(v1,v2) / sqrt(dot(v1,v1)*dot(v2,v2))`, ranges [-1,1], measures how similarly two vectors point regardless of magnitude.
- **Embedding layer**: a lookup table (`List[Vector]`) mapping discrete IDs (e.g., word IDs) to dense vectors; `forward` selects a row, `backward` only updates the gradient for the row that was actually used.
- **Hidden state**: the RNN's "memory" of everything seen so far in a sequence, updated and overwritten at every timestep.
- **LSTM / GRU**: more sophisticated RNN variants with gating mechanisms that let only part of the hidden state update/be used each step, addressing the "simple RNN" tendency to overwrite everything each call and struggle with long-range dependencies — mentioned but not implemented in the main text.

## Mental Models
- **n-grams vs. grammars trade fluency for creativity differently**: n-grams can generate surprising combinations but easily degenerate into gibberish; grammars always produce syntactically valid (if sometimes silly) sentences but require upfront rule design.
- **More constrained generation looks more fluent but is more plagiaristic**: trigram models "sound better" than bigram models specifically because they have fewer choices at each step, which also means they more often reproduce verbatim phrases from the source corpus — a fluency/originality tradeoff.
- **Embeddings encode similarity through shared context**: words appearing in similar contexts (surrounded by similar neighbor words) end up with similar vectors purely as a side effect of the prediction task — no explicit "synonym" label is ever provided.
- **RNNs solve the variable-length-sequence problem that summation can't**: naively summing/averaging word vectors loses word order; an RNN's running hidden state preserves order-dependent information across a variable-length input sequence.
- **Simple RNNs are a stepping stone, not a production tool**: the book explicitly says "you probably shouldn't use [SimpleRnn] in practice" because overwriting the entire hidden state every step makes long-range dependency learning difficult — LSTM/GRU exist specifically to fix this.

## Anti-patterns
- **Treating a naive word cloud as a meaningful visualization**: word placement conveys nothing beyond "fit here" — always consider whether axes/position can encode real data.
- **Expecting n-gram-generated text to be both fluent and non-derivative**: fluency (fewer word choices per step) and originality are in direct tension.
- **Training topic models or word embeddings on too little data**: the chapter's own LDA example admits "most likely we don't have enough data to successfully learn" clean, non-overlapping topics with only 15 short documents; similarly, word vectors typically need millions/billions of words in practice, forced to use an artificial toy dataset here.
- **Using sum/average pooling over word vectors when word order matters**: loses exactly the information ("dog bites man" vs. "man bites dog") that often carries the meaning.
- **Using a simple (non-gated) RNN for tasks needing long-range memory**: its complete hidden-state overwrite each step makes this fail in practice — reach for LSTM/GRU instead.

```python
transitions = defaultdict(list)
for prev, current in zip(document, document[1:]):
    transitions[prev].append(current)

def generate_using_bigrams() -> str:
    current = "."
    result = []
    while True:
        next_word_candidates = transitions[current]
        current = random.choice(next_word_candidates)
        result.append(current)
        if current == ".": return " ".join(result)
```
- **What it demonstrates**: a from-scratch bigram language model built purely from word-pair frequency counts.

## Reference Tables
| Technique | Input unit | Captures |
|---|---|---|
| Bigram model | word pairs | very local word statistics |
| Trigram model | word triples | more local coherence, more verbatim reuse |
| Grammar | production rules | syntactic structure (valid sentences by construction) |
| LDA | documents of words | latent topic structure across a corpus |
| Word embeddings (skip-gram) | word + context window | semantic/syntactic similarity as vector proximity |
| RNN | sequential tokens | order-dependent sequence meaning |

## Worked Example
LDA is run with K=4 topics on 15 users' short lists of data-science interests; after 1000 Gibbs-sampling iterations, inspecting each topic's most-common words lets the author hand-name them "Big Data and programming languages," "Python and statistics," "databases," and "machine learning." A toy 50-sentence corpus with templated structure (`"The {color} {noun} {verb} {adverb} {adjective} ."`) trains skip-gram word vectors (embedding_dim=5); after training, cosine-similarity pairs like `('boat','car')` at 0.998 and `('bed','cat')` at 0.998 emerge (an artifact of the small, repetitive training data), and a PCA-projected 2D scatterplot shows colors, nouns, and adjectives visually clustering by part of speech. A character-level RNN (two stacked `SimpleRnn` layers + Linear + softmax) trained on 101 Y Combinator top-startup names for 300 epochs generates new candidate names ranging from near-verbatim (Scripe, Loinbare) to creative (Benuus, Cletpo, Equite) to garbage-like (SFitreasy, GliyOx) — illustrating both the promise and the limits of character-level generation.

## Key Takeaways
1. Simple frequency-based language models (n-grams) are easy to build from scratch but trade fluency against originality — more context (trigrams) sounds better but reproduces the source more.
2. Formal grammars guarantee syntactic validity through explicit rules, at the cost of needing to design those rules by hand.
3. Gibbs sampling lets you sample from distributions you can't sample directly, as long as you know the relevant conditional distributions — this is exactly how LDA topic assignment is learned.
4. Word embeddings learn useful dense vector representations purely from a word-prediction task; similar-context words end up with similar vectors as an emergent property.
5. RNNs solve the variable-length, order-sensitive sequence problem that naive pooling (sum/average) cannot — but simple RNNs struggle with long-range dependencies, motivating LSTM/GRU in practice.
