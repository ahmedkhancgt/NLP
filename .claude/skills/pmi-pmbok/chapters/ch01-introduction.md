# Chapter 1: Introduction (The Standard for Project Management)

## Core Idea
Project management is a strategic competency: *The Standard for Project Management* defines the system within which projects operate (governance, functions, environment, culture, portfolio/program interactions) so organizations can turn project work into realized value, not just delivered outputs.

## Frameworks Introduced
- **Value delivery system**: the collection of strategic business activities (portfolios, programs, projects, products, operations) that build, sustain, or advance an organization.
  - When to use: frame any project proposal in terms of which part of the value delivery system it serves, not just its deliverable.
  - How: trace the project's outputs → outcomes → benefits → value, and name which stakeholders realize that value.
- **Operations vs. project management distinction**: operations run ongoing, repeatable value-producing work; projects are temporary and create change.
  - When to use: deciding whether an initiative should be chartered as a project or absorbed into standing operations.
  - How: check for a defined end condition (objectives met, funds exhausted, strategic need gone) — if none exists, it's operations.

## Key Concepts
- **Artifact**: a document or item created during portfolio/program/project work to help manage it.
- **Benefit**: a gain or asset realized by the organization/stakeholders from outcomes delivered.
- **Outcome**: the end result/consequence of a process or project — can be positive ("benefit") or negative ("disbenefit").
- **Output**: a product, result, or service generated by a process; may feed a successor process.
- **Portfolio**: a collection of programs, projects, and operations managed as a group to maximize value delivery.
- **Program**: a group of related projects/activities managed together for benefits unavailable from managing them individually — "not merely large projects."
- **Project**: a temporary initiative in a unique context undertaken to create value.
- **Project governance**: the adaptable framework guiding project activities, providing structure, roles, and decision-making models (e.g., RACI, governance boards).
- **Value**: excess of financial and nonfinancial benefits over investment; perceived differently by different stakeholders (ROI for organizations, convenience for customers, societal impact for NGOs/governments).
- **Value delivery system**: see Frameworks above.

## Mental Models
- Think of a project as moving an organization from a **current state** → (optional **transition state**) → **future state** (Figure 1-1); the project's value is the gap it closes.
- Use the portfolio/program/project/operations distinction (Table 1-1) when scoping how an initiative should be structured: portfolios optimize strategic alignment, programs optimize cross-project synergy, projects optimize scoped delivery.
- Organizational governance sets direction/control org-wide; project governance applies that at the single-project level — don't conflate the two when escalating decisions.

## Anti-patterns
- **Treating "meeting or exceeding value" as license for gold-plating or scope creep**: the standard explicitly warns this is not what value-driven decision-making means — it means satisfying stakeholder needs, not adding unrequested scope.
- **Ignoring the project→operations handoff**: failing to transfer deliverables, resources, and knowledge to operations at closeout breaks the value delivery system's continuity.

## Reference Tables

**Table 1-1. Comparative Overview of Portfolios, Programs, and Projects**

| Dimension | Portfolios | Programs | Projects |
|---|---|---|---|
| Definition | Collection of programs/projects/operations managed as a group to maximize value and meet strategic objectives | Related projects/activities managed in coordination for benefits unavailable individually | Temporary initiative in a unique context to create value |
| Scope | Organizational scope aligned with strategy | Integrates scope of component projects/subprograms | Defined objectives, progressively elaborated |
| Change | Continuous monitoring/adjustment to strategic priorities | Adaptable to optimize value at program level | Adaptable to enable/maximize value delivery |
| Planning | Strategic planning, priority definition, resource allocation | High-level, tracks interdependencies | Predictive, adaptive, or hybrid |
| Monitoring | Strategic changes and resource allocation | Progress of component projects, benefits realization | Outputs and value |
| Success | Strategic value delivery, alignment with vision/mission | Collective benefit/value delivery, strategic alignment | Delivered value worth the effort/expense (quality, timeliness, budget, sustainability, stakeholder satisfaction) |

## Key Takeaways
1. A project's purpose is organizational change toward a future state — always name the current/future state gap, not just the deliverable.
2. Distinguish portfolio/program/project/operations by their governance and success-measurement focus (Table 1-1), not just by size.
3. "Meeting or exceeding value" is a decision filter against scope creep/gold-plating, not permission for it.
4. Project governance (single project) nests inside organizational governance (enterprise-wide) — escalate accordingly.
5. Plan the operations handoff at the start, not just the end, of a project.
